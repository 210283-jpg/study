# Feature Specification: 讀書時間與成果紀錄系統

**Feature Branch**: `001-study-tracking`  
**Created**: 2025-11-03  
**Status**: Draft  
**Input**: 我要做一個讀書時間付出努力和成果回報正相關紀錄的網頁

## 概述

本功能建立一個互動式網頁工具，幫助學習者追蹤學習投入與成果之間的關係。使用者可記錄每次學習會議的時間、科目、職業付出度與成果，系統自動分析並視覺化這些資料，展示學習效率趨勢。

## 使用者情境與測試 *(必需)*

### 使用者故事 1 - 記錄單次學習會議 (優先級: P1)

學習者完成一次讀書會議後，需要快速記錄投入時間、科目、職業付出度及學習成果。記錄應簡潔直觀，讓使用者在 1 分鐘內完成。

**為何此優先級**：這是系統的核心功能，沒有記錄能力則無法進行任何分析。所有其他功能都依賴於此。

**獨立測試**：僅實現此功能即可驗證：使用者能成功輸入並保存一條學習記錄，記錄包含時間、科目、職業付出度、成果等資訊。

**驗收場景**：

1. **Given** 使用者進入應用主頁，**When** 點擊「新增記錄」按鈕，**Then** 出現記錄表單
2. **Given** 表單顯示所有必填欄位，**When** 使用者填寫所有欄位並點擊「保存」，**Then** 記錄被保存且頁面確認成功
3. **Given** 表單已填寫，**When** 使用者清除投入時間欄位，**Then** 系統顯示驗證錯誤訊息
4. **Given** 記錄已保存，**When** 使用者重新進入應用，**Then** 之前保存的記錄仍存在

---

### 使用者故事 2 - 檢視學習歷史記錄 (優先級: P1)

學習者希望查看過往所有的學習記錄，了解學習的進展與趨勢。應能按科目、時間範圍篩選，並清楚展示每筆記錄的關鍵資訊。

**為何此優先級**：記錄存儲後需要檢視功能才能產生價值。此功能是數據分析的基礎。

**獨立測試**：實現此功能後，使用者能檢視所有保存的記錄、篩選記錄、並確認資料正確顯示。

**驗收場景**：

1. **Given** 系統中存在多筆學習記錄，**When** 使用者進入「歷史記錄」頁面，**Then** 所有記錄以清單形式顯示
2. **Given** 歷史記錄頁面，**When** 使用者按科目篩選，**Then** 僅顯示該科目的記錄
3. **Given** 歷史記錄頁面，**When** 使用者選擇日期範圍，**Then** 僅顯示該範圍內的記錄
4. **Given** 記錄清單，**When** 使用者點擊某筆記錄，**Then** 顯示該記錄的詳細資訊

---

### 使用者故事 3 - 視覺化學習效率分析 (優先級: P1)

系統自動分析使用者的學習數據，產生視覺化圖表展示投入時間與成果的正相關性。使用者能直觀看到努力與回報的關係。

**為何此優先級**：這是系統的核心價值主張——視覺化展示努力與回報的關係。無此功能則功能不完整。

**獨立測試**：實現此功能後，系統能基於已保存的記錄產生至少一種圖表（如散點圖或折線圖），清楚展示投入與成果的趨勢。

**驗收場景**：

1. **Given** 系統中存在多筆記錄，**When** 使用者進入「分析」頁面，**Then** 顯示投入時間 vs. 成果的圖表
2. **Given** 分析圖表，**When** 使用者按科目篩選，**Then** 圖表更新以反映該科目的數據
3. **Given** 圖表，**When** 使用者懸停或點擊數據點，**Then** 顯示對應記錄的詳細資訊
4. **Given** 分析頁面，**When** 系統計算相關性，**Then** 顯示投入時間與成果的相關係數或趨勢描述

---

### 使用者故事 4 - 編輯與刪除記錄 (優先級: P2)

使用者需要能修正錯誤的記錄或刪除過時的數據。編輯功能應保留原始紀錄時間戳記供審計。

**為何此優先級**：提高系統實用性，但不是核心功能。可在後續迭代中加入。

**獨立測試**：使用者能成功編輯記錄欄位、保存變更，以及刪除不需要的記錄。刪除後記錄不再出現在任何清單或圖表中。

**驗收場景**：

1. **Given** 歷史記錄中存在某筆記錄，**When** 使用者點擊「編輯」，**Then** 表單填入該記錄的原始資訊
2. **Given** 編輯表單，**When** 使用者修改欄位並保存，**Then** 記錄更新，編輯時間被記錄
3. **Given** 歷史記錄中存在某筆記錄，**When** 使用者點擊「刪除」並確認，**Then** 記錄被移除

---

### 使用者故事 5 - 統計摘要與insights (優先級: P2)

在儀表板上展示關鍵統計數據，如本週總投入時間、平均成果評分、最高效率科目等，幫助使用者快速了解學習狀況。

**為何此優先級**：提供快速摘要增加使用體驗，但不影響核心功能。可在後續迭代加入。

**獨立測試**：系統能根據已保存記錄計算並正確顯示統計數據。

**驗收場景**：

1. **Given** 儀表板頁面，**When** 使用者進入，**Then** 顯示本週總投入時間、平均成果分數
2. **Given** 儀表板，**When** 系統計算最高效率科目，**Then** 清楚標示該科目及其效率數值

---

### 邊界情況

- 若使用者在極短時間內（< 1 分鐘）創建記錄，系統如何處理？ **[已澄清]** 接受，無最小時間限制
- 若成果評分為負值，系統應如何顯示？ **[已澄清]** 不接受負值，在表單驗證層拒絕
- 若使用者輸入非常大的投入時間（如 24+ 小時），系統是否應警告或拒絕？ **[已澄清]** > 480 分鐘顯示警告但允許提交
- 若沒有任何記錄，分析圖表應顯示什麼？ **[已澄清]** 顯示友善空狀態提示與引導按鈕
- 若用戶建立相同名稱的科目，系統如何處理？ **[已澄清]** 科目名稱必須唯一，表單驗證層防止重複
- 若用戶嘗試下載資料但瀏覽器不支援，系統如何處理？ **[已澄清]** 顯示友善錯誤訊息，提示用戶升級瀏覽器
- 若用戶刪除預設科目後重新載入，應恢復還是保留刪除狀態？ **[已澄清]** 保留刪除狀態（用戶隱藏選擇持久化）
- 若記錄數超過 1000 筆，性能如何？ **[已澄清]** 應實現分頁或虛擬滾動確保載入時間 < 2 秒

## 需求 *(必需)*

### 功能需求

- **FR-001**: 系統 MUST 允許使用者輸入單次學習會議的投入時間（分鐘數），上限驗證：> 480 分鐘時顯示警告
- **FR-002**: 系統 MUST 提供預設科目清單（10 個常見科目）供選擇，預設科目可由用戶隱藏或刪除，每個科目綁定固定的成果測量單位
- **FR-003**: 系統 MUST 允許使用者建立自訂科目，自訂科目時從預設成果單位清單選擇或輸入自訂單位
- **FR-004**: 系統 MUST 允許使用者評估職業付出度（1-5 級別：極差、差、中等、好、極佳）
- **FR-005**: 系統 MUST 允許使用者記錄學習成果，成果欄位 MUST 支援即時計時功能，所有輸入需通過雙層驗證（前端 + 保存時）
- **FR-006**: 系統 MUST 持久化保存所有記錄，使用 LocalStorage 快取 + IndexedDB 持久化機制；預設科目寫死代碼，自訂科目存儲在 IndexedDB
- **FR-007**: 系統 MUST 允許使用者檢視所有歷史記錄
- **FR-008**: 系統 MUST 支援按科目篩選記錄
- **FR-009**: 系統 MUST 支援按時間範圍篩選記錄
- **FR-010**: 系統 MUST 自動產生投入時間 vs. 成果的視覺化圖表，使用功能豐富的圖表庫（D3.js 或 ECharts）
- **FR-011**: 系統 MUST 計算並顯示投入時間與成果的相關性分析（需最少 2 筆記錄，低於 2 筆顯示「無法計算」），提供三種檢視：(a) 皮爾遜相關係數、(b) 趨勢線、(c) 等級評分
- **FR-012**: 系統 MUST 允許使用者編輯已保存的記錄
- **FR-013**: 系統 MUST 允許使用者刪除記錄（需確認操作）
- **FR-014**: 系統 MUST 在每條記錄上記錄建立與最後編輯的時間戳
- **FR-015**: 系統 MUST 在分析頁面無記錄時顯示友善的空狀態提示與快速新增記錄按鈕
- **FR-016**: 系統 MUST 提供資料匯出功能，支援 JSON 與 CSV 雙格式下載
- **FR-017**: 系統 MUST 採用多頁應用（MPA）架構，每個主要功能模塊為獨立 HTML 頁面（記錄頁、歷史記錄頁、分析頁、儀表板頁）

### 關鍵實體

- **學習記錄 (Study Session)**：
  - 投入時間（分鐘，> 480 時觸發警告）
  - 科目名稱（預設清單或用戶自訂）
  - 職業付出度（1-5 級別）
  - 成果（基於科目的測量單位，支援即時計時）
  - 建立時間戳
  - 最後編輯時間戳
  - 可選備註

- **科目 (Subject)**：
  - 科目名稱（唯一，預設 10 個 + 用戶自訂）
  - 成果測量單位（預設清單：分數、習題數、頁數、章節數 + 用戶自訂）
  - 是否為預設科目（布林值）

## 成功標準 *(必需)*

### 可測量的成果

- **SC-001**: 使用者能在 60 秒內完成一筆完整的學習記錄輸入
- **SC-002**: 系統能正確保存並檢索所有記錄，100% 的保存操作成功率
- **SC-003**: 篩選功能能準確返回符合條件的記錄（篩選精確度 100%）
- **SC-004**: 視覺化圖表能正確反映已保存的記錄數據（圖表數據準確度 100%）
- **SC-005**: 相關性分析能產生有意義的 insights（需最少 2 筆記錄，皮爾遜相關係數計算正確，趨勢線擬合準確，等級評分與數值相符）
- **SC-006**: 使用者首次加載應用時需要 < 2 秒
- **SC-007**: 頁面在桌面、平板、手機上可用（響應式設計無破損）
- **SC-008**: 系統支援至少 1000 筆記錄且不出現明顯延遲（載入時間 < 2 秒）
- **SC-009**: 90% 的首次使用者能不閱讀文件就成功記錄一筆數據
- **SC-010**: 編輯與刪除操作的確認率 > 95%（減少誤操作）
- **SC-011**: 投入時間超過 480 分鐘時，系統正確顯示警告訊息，用戶仍可繼續提交
- **SC-012**: 用戶可成功下載 JSON 與 CSV 格式的完整資料備份
- **SC-013**: 計時器功能測量誤差 < 1 秒
- **SC-014**: 所有用戶輸入通過雙層驗證（前端驗證成功率 100%，保存時驗證成功率 100%）
- **SC-015**: 相關性分析在數據不足時（< 2 筆）正確顯示「無法計算」提示

## 假設

- 系統採用多頁應用（MPA）架構，每個功能模塊為獨立 HTML 頁面
- 預設科目寫死在代碼中，可由用戶隱藏或刪除（用戶選擇被持久化到 IndexedDB）
- 自訂科目與其配置（成果單位）完全存儲在 IndexedDB
- 所有用戶輸入採用雙層驗證（前端 + 保存時）確保數據完整性
- 圖表使用功能豐富的庫（D3.js 或 ECharts）
- 相關性分析需最少 2 筆記錄，少於 2 筆時顯示「無法計算」
- 職業付出度使用 1-5 級別量表
- 成果欄位支援即時計時功能，用戶可在記錄時啟動計時器
- 投入時間超過 480 分鐘（8 小時）時系統顯示警告，但用戶仍可提交
- 相關性分析同時提供皮爾遜相關係數、趨勢線、等級評分三種指標
- 系統支援 JSON 與 CSV 雙格式資料匯出
- 成果評分為正值（範圍由使用者定義，依科目測量單位而異）
- 使用者時間投入為正整數（以分鐘計）
- 系統無需連接外部 API 或後端服務（純靜態前端）
- 使用者瀏覽器支援 LocalStorage 與 IndexedDB 機制
- 系統無需用戶認證（單機使用或分享連結）
- 資料使用 LocalStorage 快取 + IndexedDB 持久化的雙層架構

---

## 約束

- 必須是可部署至 GitHub Pages 的靜態網站
- 不依賴任何後端伺服器
- 所有數據保存在用戶本機（LocalStorage 或 IndexedDB）
- 需遵守憲章的可訪問性標準（WCAG 2.1 AA）
- 首頁加載時間 < 3 秒
